Evidence-Based IAM Recommendations (NIST SP 800-63B)

CT (10.1% mean) and CBA (9.0% mean) show sustained elevation across all 26 weeks—a pattern consistent with persistent credential friction (such as forgotten passwords, password reuse, or input errors, though aggregate counts alone cannot distinguish user typos from automated guessing). Per NIST SP 800-63B, avoid forced periodic password rotation and symbol-composition rules (which increase lockouts); instead, enroll these cohorts in MFA and enforce 12+ character passphrases screened against breached-password blocklists.

CIC and CoE maintain low typical medians (~3.9%–4.3%) but exhibit isolated single-week Desktop/Laptop surges (>18%), consistent with automated credential-stuffing or spraying bursts. While MFA does not prevent external bots from generating failed primary-login attempts, requiring MFA blocks successful account takeovers when passwords are leaked, and progressive rate-limiting/throttling curbs burst volume.

Simulated Mobile logins sit ~1.4 percentage points above Desktop/Laptop baselines across all 8 colleges and rise together during Midterm (Weeks 8–9) and Final Exam (Weeks 17–18) windows. Adding a "Show Password" reveal toggle, disabling auto-capitalization on username fields, and sending pre-exam self-service reset reminders reduces avoidable user lockouts.

About the Project

Identity & Access Management (IAM)

KandadoHoy (Failed UVE Logins Across USeP Colleges) is an information security analytics dashboard developed to help USeP's IT office and college deans evaluate whether weekly failed login rates on the University Virtual Environment (UVE) differ significantly across 8 USeP colleges. Distinguishing chronic password-hygiene gaps from sudden multi-week credential bursts enables targeted cybersecurity awareness campaigns and phased Multi-Factor Authentication (MFA) rollout.

Data Transparency Notice: The records presented in this dashboard are simulated 26-week college-level summaries generated for statistical analysis and academic demonstration; they do not contain actual student credentials or live USeP authentication logs.

1. Metric Formula & Pooled Aggregation Rule

Each record captures weekly UVE login telemetry across 8 USeP colleges over 26 academic weeks segmented by 3 device types (Mobile, Desktop/Laptop, Tablet). When viewing all devices combined, counts are pooled prior to division to avoid Simpson's Paradox:

failed_login_rate = (sum(failed_logins) / sum(login_attempts)) × 100

2. Explicit Simulation Assumptions & Random Seeds

  • Random Seeds & Scenarios: Deterministic Mulberry32 PRNG with seed = 20260926 for the Effect Scenario (modeled differences + bursts) and seed = 20260927 for the Null-Data Control (identical 5.5% baseline across all 8 colleges, zero injected bursts).
  • Cohort Sizes (Total = 15,850 baseline active users/week): CAS (~2,950), CoE (~2,650), CEd (~2,400), CBA (~2,200), CT (~1,950), CIC (~1,650), CAEc (~1,100), and CDM (~950).
  • Device-Type Multipliers (+1.4 pp Mobile Effect): Mobile accounts for 54% of users (3.4 attempts/user/wk, 1.18× baseline rate multiplier), Desktop/Laptop for 36% (4.1 attempts/user/wk, 0.86× multiplier), and Tablet for 10% (2.3 attempts/user/wk, 0.96× multiplier). Across the 8 colleges, Mobile's 1.18× vs. Desktop's 0.86× multiplier produces a ~+1.4 percentage point higher baseline failure rate on Mobile.
  • Effect Scenario Elevations & Bursts: CT (9.8% base) and CBA (8.7% base) are generated with persistent chronic elevation across all 26 weeks. CIC (3.9% base) and CoE (4.3% base) have low baselines with injected Desktop/Laptop credential bursts (CIC Wks 11 & 19 at 28.5% & 24.5%; CoE Wk 14 at 22.5%).
  • Shared Academic Calendar Friction: Both scenarios apply a synchronized 1.26× failure-rate multiplier and 1.22× attempt-volume multiplier across all 8 colleges during Midterm (Weeks 8–9) and Final Exam (Weeks 17–18) periods—motivating a week-blocked repeated-measures test.

3. Python Generator & Statistical Verification Script

import numpy as np
import pandas as pd
import scipy.stats as stats
from statsmodels.stats.multitest import multipletests

# 1. Reproducible Data Generator (Matches KandadoHoy Dashboard Seeds)
def simulate_uve_cohort(scenario="effect", seed=20260926):
    rng = np.random.default_rng(seed)
    colleges = [
        ("CT", 1950, 0.098), ("CBA", 2200, 0.087), ("CIC", 1650, 0.039),
        ("CoE", 2650, 0.043), ("CAEc", 1100, 0.051), ("CAS", 2950, 0.048),
        ("CEd", 2400, 0.046), ("CDM", 950, 0.044),
    ]
    devices = [("Mobile", 0.54, 3.4, 1.18), ("Desktop/Laptop", 0.36, 4.1, 0.86), ("Tablet", 0.10, 2.3, 0.96)]
    exam_weeks = {8, 9, 17, 18}
    rows = []
    for week in range(1, 27):
        exam_mult = 1.26 if week in exam_weeks else 1.0
        att_mult = 1.22 if week in exam_weeks else 1.0
        wave = 1.0 + 0.05 * np.sin((week / 26.0) * 2 * np.pi)
        for code, base_u, base_r in colleges:
            eff_r = 0.055 if scenario == "null" else base_r
            for dev, share, apu, r_mult in devices:
                users = round(base_u * share * wave * rng.uniform(0.95, 1.05))
                attempts = max(users, round(users * apu * att_mult * rng.uniform(0.94, 1.06)))
                rate = eff_r * r_mult * exam_mult * rng.uniform(0.88, 1.12)
                if scenario == "effect" and dev == "Desktop/Laptop":
                    if code == "CIC" and week in (11, 19): rate = 0.285 if week == 11 else 0.245
                    if code == "CoE" and week == 14: rate = 0.225
                failed = min(attempts, max(1, round(attempts * rate)))
                rows.append((week, code, dev, users, attempts, failed))
    return pd.DataFrame(rows, columns=["week", "college", "device_type", "active_users", "login_attempts", "failed_logins"])

# 2. Pool device counts per (week, college) before computing rate (avoids Simpson's Paradox)
df = simulate_uve_cohort(scenario="effect", seed=20260926)
pooled = df.groupby(["week", "college"], as_index=False).sum(numeric_only=True)
pooled["rate"] = (pooled["failed_logins"] / pooled["login_attempts"]) * 100
piv = pooled.pivot(index="week", columns="college", values="rate")  # 26 week blocks x 8 colleges

# 3. Week-Blocked Omnibus Friedman Test + Kendall's W Effect Size
b, k = piv.shape
chi2_r, p_friedman = stats.friedmanchisquare(*[piv[c] for c in piv.columns])
kendalls_w = chi2_r / (b * (k - 1))
print(f"Friedman chi2_r(df={k-1}) = {chi2_r:.4f}, p = {p_friedman:.6f}, Kendall's W = {kendalls_w:.4f}")

# 4. Leave-One-College-Out (LOO) Paired Wilcoxon Post-Hoc + Holm Correction
raw_p, codes = [], list(piv.columns)
for c in codes:
    others = df[df["college"] != c].groupby("week", as_index=False).sum(numeric_only=True)
    loo_rate = (others["failed_logins"] / others["login_attempts"]) * 100
    _, p_w = stats.wilcoxon(piv[c].values, loo_rate.values)
    raw_p.append(p_w)

_, p_holm, _, _ = multipletests(raw_p, alpha=0.05, method="holm")
for c, p0, ph in zip(codes, raw_p, p_holm):
    print(f"  {c:4s}: median={piv[c].median():.2f}%, raw_p={p0:.6f}, holm_p={ph:.6f}")
